# УрФУ Столовая — сайт загруженности столовых НВК

Веб-приложение для трёх столовых Новокольцовского кампуса УрФУ: карта
кампуса с метками загруженности, страница каждого корпуса с оценкой
«насколько людно» и всплывающим меню.

## Возможности

**Для посетителя (гость):**
- Карта кампуса с метками-пинами: зелёный — свободно, оранжевый — средняя,
  красный — высокая, серый — мало данных. На каждой метке — счётчик
  «сколько человек проголосовало».
- Страница корпуса `/corpus/<id>`: расположение столовой, плашка текущего
  статуса, кнопки «Оцените загруженность сейчас» (обновляется без
  перезагрузки), всплывающее меню с категориями и блюдами.
- Голосование за загруженность: можно голосовать не чаще раза в минуту;
  у одного человека хранится один голос — повторный голос обновляет
  старый, а не добавляет новый.
- Отметка «блюдо отсутствует»: если в меню блюда нет, а работник не успел
  обновить меню, гость сам помечает блюдо. Пометка:
  - выглядит иначе, чем «Нет в наличии» от работника (серая пунктирная
    рамка и серое название, как у скрытых блюд, плюс тег «гости отметили
    отсутствующее»);
  - сбрасывается **ровно в 00:00 по Екатеринбургу** — всё, что отмечено
    вчера и раньше, исчезает;
  - может быть снята любым гостем (кнопка «Убрать пометку») или работником
    (кнопка «Сбросить пометку гостей»).

**Для работника (пароль `2626`):**
- Редактирование меню: добавлять, переименовывать, скрывать «Нет в наличии»
  и удалять категории и блюда.
- Изменение расположения столовой.
- Сброс гостевых пометок «блюдо отсутствует».

- Мобильная адаптация (mobile-first).

## Как считается загруженность

Источник данных о загруженности — голоса посетителей (кнопки «Свободно /
Средне / Много народу»). Голоса хранятся в SQLite (`backend/data/votes.db`).

**Пороги, и почему такие числа:**

- Уровням соответствуют числа: `low = 1`, `medium = 2`, `high = 3`.
- Каждому голосу даётся **вес по свежести**: голосу младше 3 минут — вес 3,
  старше — вес 1. Так свежие мнения влияют на статус сильнее старых.
- Считается **взвешенное среднее** всех голосов за последние 10 минут.
  Среднее между 1 и 2 (то есть `< 1.5`) — «свободно»; между 2 и 3
  (`< 2.5`) — «средняя»; от 2.5 — «высокая». Эти числа — ровно середины
  между уровнями, поэтому статус показывает, к какому уровню ближе
  мнение людей.
- **Доверие** — доля веса голосов, которые согласны с итоговым уровнем
  (0..1). Если все голоса одинаковые, доверие 100%.
- Если голосов меньше 2 — данных почти нет, показывается `NO_DATA` (серый
  статус): один-единственный голос может быть случайным. Уже при 2 голосах
  маркер на карте начинает показывать реальный цвет статуса.
- Голосовать за одну столовую можно не чаще раза в минуту — защита от
  накрутки (повторный голос раньше времени возвращает HTTP 429).
- В обед (12:00–14:00) доверие повышается на 0.10 (но не больше 1) — в часы
  пик данных обычно больше, статус увереннее.

**Единицы измерения и частота опроса:**

- Единицы: количество голосов штуками *за последние 10 минут*; число
  проголосовавших — разные посетители (у каждого человека один голос);
  доверие — доля от 0 до 1 (на экране в процентах); уровень —
  low/medium/high (по-русски: «Свободно», «Средне», «Много народу»).
- Поллинг страницы корпуса: `GET /status/<id>` каждые **2 секунды**.
- Обновление карты на главной: `GET /api/loads` каждые **2 секунды**.
- Сервер кеширует расчёт статуса на **10 секунд** (ответ быстрее).

**Контур замкнут:** голос (измерение) → веса и пороги (правило решения) →
новый статус (реакция) → плашка и пин меняются на страницах (видимое
изменение состояния).

**Что случится при «отказе датчика»** (то есть если оценки перестают
приходить): через 10 минут после последнего голоса голосов за окно
останется меньше 2, и статус станет `NO_DATA` — плашка «Пока мало оценок»
и серые метки на карте. Как только появятся хотя бы 2 свежих голоса,
статус и маркеры вернутся.
Если файл базы `votes.db` пропал или повреждён — он создаётся заново при
запуске, ничего не падает.

## Маршруты

| Метод и путь | Доступ | Назначение |
|---|---|---|
| `GET /` | все | Главная: карта кампуса с метками |
| `GET /corpus/<id>` | все | Страница корпуса (или 404) |
| `GET /api/loads` | все | Загруженность всех корпусов для карты |
| `GET /status/<id>` | все | Текущий статус корпуса (JSON, кеш 10 с) |
| `POST /corpus/<id>/report-load` | все | Голос `{"load": "low\|medium\|high"}`, возвращает свежий статус |
| `POST /corpus/<id>/canteen-location` | работник | Изменить расположение столовой |
| `GET /corpus/<id>/menu` | все | Меню (JSON). Гостям — только видимое, работнику — всё |
| `POST /corpus/<id>/menu/items/<item_id>/guest-missing` | все | Поставить/снять гостевое «блюдо отсутствует» `{"mark": true\|false}` |
| `POST/PUT/PATCH/DELETE /corpus/<id>/menu/categories/...` | работник | Редактирование категорий |
| `POST/PUT/PATCH/DELETE /corpus/<id>/menu/items/...` | работник | Редактирование блюд |
| `POST /login`, `POST /logout` | — | Вход/выход из режима работника |

Пароль работника: **2626** (хранится открытым текстом в `backend/run.py`,
чтобы его было легко найти в коде).

## Технологии

- Python 3 + Flask (Jinja2-шаблоны), SQLite для голосов.
- Чистые HTML/CSS, JS для оценки, поллинга и редактирования меню
  (`backend/static/js/main.js`).
- Корпуса (статичные данные) — в `backend/run.py`.
- Расположения столовых и меню — JSON-файлы в `backend/data/`
  (`locations.json`, `menu.json`); гостевые пометки — `guest_reports.json`.
- CSRF-защита всех мутирующих запросов (заголовок `X-CSRF-Token`).

## Запуск

```bash
cd backend
python -m venv venv
venv\Scripts\activate        # Windows
pip install -r requirements.txt
python run.py
```

Откройте http://127.0.0.1:5000/ в браузере (мобильный вид — Ctrl+Shift+M).
Порт по умолчанию — 80 (переопределяется переменной `PORT`), режим отладки —
через `FLASK_DEBUG=1`.

## Структура проекта

```
backend/
  run.py              — сервер: страницы, API, вход работника, меню
  vote.py             — голосование: база SQLite, расчёт статуса
  requirements.txt    — зависимости Python
  data/
    locations.json    — где находится столовая в каждом корпусе
    menu.json         — меню (категории и блюда, цены, "нет в наличии")
    guest_reports.json— гостевые пометки «блюдо отсутствует» (создаётся сам)
    votes.db          — голоса (SQLite, создаётся сам)
  templates/          — HTML-страницы (index.html, corpus.html)
  static/
    js/main.js        — весь клиентский JavaScript
    img/              — картинки: карта, метки, плашки, кнопки, логотип
```

## Что можно изменить позже

- Названия, адреса и этажи столовых — список `_CORPS` в `backend/run.py`.
- Реальные блюда и цены — `backend/data/menu.json` (сейчас примерные).
- Изображения — `backend/static/img/` (логотип, карта, пины, плашки, меню).
- Пароль работника — `_ADMIN_PASSWORD` в `backend/run.py`.
