# Пользовательские сценарии — " Столовой УРФУ"

     **1. Роли пользователей**

В системе предусмотрены две основные роли:

      *** Студент ***

Студент использует сервис для просмотра информации о столовых УрФУ, их загруженности и доступности позиций меню.

      ***Работник столовой***

Работник столовой имеет доступ к административной части системы. Он может управлять информацией о меню своей столовой: изменять названия позиций и их наличие.

###

      *** 2. Сценарий студента ***

### Шаг 1. Открытие сайта

Студент открывает веб-сайт сервиса.

Перед ним отображается **главная страница**.

На главной странице пользователь может перейти к работе с сервисом.


### Шаг 2. Авторизация

Студент проходит **авторизацию**.

После успешной авторизации он получает доступ к функциональности сервиса как обычный пользователь.


### Шаг 3. Выбор столовой

После входа пользователь выбирает интересующую его столовую.

Например, если в системе несколько столовых УрФУ, пользователь выбирает ту, информацию о которой он хочет посмотреть.

После выбора открывается информация о выбранной столовой.


### Шаг 4. Просмотр статуса загруженности

На странице столовой пользователь видит её **статус загруженности**.

Статус позволяет пользователю понять, насколько столовая загружена в данный момент.

Таким образом, пользователь может принять решение, стоит ли ему идти в эту столовую.


### Шаг 5. Оценка статуса

Пользователь может оценить текущий статус с помощью специальных **кнопок оценки**.

То есть пользователь взаимодействует с системой и передаёт свою оценку текущей ситуации в столовой.


### Шаг 6. Открытие меню

Пользователь нажимает кнопку **«Меню»**.

После нажатия открывается **всплывающее окно**.


### Шаг 7. Просмотр позиций меню

Во всплывающем окне отображаются **позиции меню**.

Пользователь может ознакомиться с представленными товарами / блюдами.


### Шаг 8. Проверка наличия

Для каждой позиции пользователь видит информацию о её **наличии**.

Таким образом, пользователь может понять, какие позиции меню доступны, а каких в данный момент нет.


### Полный сценарий студента

**Главная страница → Авторизация → Выбор столовой → Просмотр статуса загруженности → Оценка статуса → Кнопка «Меню» → Всплывающее окно → Просмотр позиций меню → Проверка наличия позиций.**


            *** 3. Сценарий работника столовой ***

### Шаг 1. Открытие сайта

Работник столовой открывает тот же веб-сайт.

Он попадает на **главную страницу**.


### Шаг 2. Выбор роли «Я работник»

На главной странице работник нажимает отдельную кнопку:

**«Я работник»**.

Эта кнопка предназначена для перехода к авторизации работников столовой.


### Шаг 3. Авторизация работника

После нажатия кнопки открывается форма авторизации.

Работник вводит свой **пароль**.


### Шаг 4. Вход в административную часть

После успешной авторизации работник получает доступ к системе **как администратор**.

То есть обычный пользователь и работник имеют разные возможности.


### Шаг 5. Выбор своей столовой

Работник выбирает столовую, информацией которой он управляет.

После выбора открывается соответствующая информация о столовой.


### Шаг 6. Открытие меню

Работник переходит в **меню своей столовой**.

В отличие от обычного пользователя, работник может не только просматривать меню, но и изменять его.


### Шаг 7. Редактирование названий позиций

Работник может изменить **название позиции меню**.

Например, если название блюда изменилось, работник может обновить его в системе.


### Шаг 8. Изменение наличия

Работник может изменить информацию о **наличии позиции**.

Например:

**Позиция есть → Позиции нет**

или

**Позиции нет → Позиция есть**

Таким образом, информация, которую видит студент, может обновляться работником столовой.


### Шаг 9. Сохранение изменений

После внесения изменений работник сохраняет обновлённую информацию.

После этого актуальные данные меню должны отображаться пользователям.


### Полный сценарий работника

**Главная страница → «Я работник» → Авторизация → Вход как администратор → Выбор столовой → Меню → Редактирование названий → Изменение наличия → Сохранение изменений.**


# 4. Взаимодействие двух ролей

Здесь находится **главная логика нашего продукта**:

**Работник столовой**
↓
обновляет меню и наличие позиций
↓
**Система**
↓
хранит актуальную информацию
↓
**Студент**
↓
открывает столовую и смотрит меню и наличие.

То есть студент **получает информацию**, а работник столовой **поддерживает эту информацию в актуальном состоянии**.
